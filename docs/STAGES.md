# Lifecycle stages

GitLab's DevSecOps lifecycle has nine stages. This table says what ModelGate does in each one
and where the proof is. A proof is a link to a real GitLab page from this project: a pipeline,
a job, a merge request, a Release, an environment, the Pages site. Until a stage has one, it
says **pending**. The README's stage map links to the project page where each stage shows up.

| Stage | What ModelGate does | GitLab feature | Proof |
| --- | --- | --- | --- |
| Plan | Not covered. ModelGate starts at the training change; it does not plan work. | | not covered |
| Create | A training change on a branch is the unit of work. The flow writes the model card and the decision record onto the same branch, and opens or updates one merge request per branch, titled and labelled by the verdict. A second flow, ModelGate Ask, answers reviewers' questions on the merge request when mentioned. | Merge requests, labels, two GitLab Duo custom flows (Pipeline events and Mention triggers) | [!5 GO](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/merge_requests/5), [!4 NEEDS REVIEW](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/merge_requests/4) with a ModelGate Ask reply, [!3 NO-GO](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/merge_requests/3), [!2 GO, the first champion](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/merge_requests/2) |
| Verify | Every training change (to `config/`, `modelgate/` or `requirements.txt`, a `[train]` commit, or a manual run) trains the challenger and evaluates it on a fixed holdout, overall and per segment. Six published rules give a deterministic GO, NEEDS REVIEW or NO-GO. The unit tests run alongside. | CI/CD pipelines, JUnit test report | [pipeline #2993257463](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/pipelines/2993257463) (the 0.2.0 GO candidate on `demo-go`) |
| Package | Each candidate is registered as `<version>-rc.<pipeline>`. The promoted model is registered as `<version>`, in the Model Registry when the job token is accepted and in the generic package registry otherwise. | Model Registry, package registry | [package registry](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/packages): `modelgate-model` 0.1.0-rc.5 to 0.2.0 (the Model Registry refused the job token) |
| Secure | picklescan checks the model file against a module allowlist. pip-audit checks the dependency lock, with OSV severities, and a HIGH or CRITICAL finding blocks the verdict. SAST and secret detection run on every branch pipeline. | SAST and Secret Detection templates | `semgrep-sast` and `secret_detection` in [pipeline #2993257463](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/pipelines/2993257463); the scan result in each [decision record](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/tree/main/models/decisions) |
| Release | Merging a GO candidate triggers `promote`. It confirms that the default branch reproduces the approved metrics exactly, then creates the Release `model-v<version>` with the model card as its notes. | Releases (REST API with `CI_JOB_TOKEN`) | [model-v0.2.0](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/releases/model-v0.2.0), [model-v0.1.0](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/releases/model-v0.1.0) |
| Configure | Everything the automation runs on is configuration in the repository, applied by CI and the flow. The `production` environment, its tier and its URL (the dashboard) are declared in `.gitlab-ci.yml`, and `deploy_production` records each promoted version there. The flow's own runtime, its Python setup, cache and network allow-list, is `.gitlab/duo/agent-config.yml`. The gate rules, the SCI constants and the reviewers are `config/*.yaml`. | Environments and deployments, Agent Platform runtime configuration | `deploy_production` in [pipeline #2993295150](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/pipelines/2993295150) (0.2.0) and [#2993152468](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/pipelines/2993152468) (0.1.0); [environments](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/environments) |
| Monitor | A nightly schedule scores a drifted batch with the champion: AUC on the batch against the holdout, and PSI per feature, with an alert past the limits in `config/thresholds.yaml`. The dashboard charts the AUC history and lists the latest PSI per feature, and the flow writes the champion's latest drift result into every new model card. | Pipeline schedules, Pages | [scheduled pipeline #2993225960](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/pipelines/2993225960) and the [dashboard](https://showcase-2dd78a.gitlab.io/) drift chart, with an alert on `utilization` |
| Govern | The gate rules are versioned config, and every candidate's rule results are committed as a decision record. A person must merge: the flow requests a review from the people in `config/review.yaml` on every GO and NEEDS REVIEW merge request, and CODEOWNERS makes them owners of the champion, the gate rules and the flow's instructions. The flow can never merge or change settings. Every candidate's SCI is reported, and so is the total carbon spent to reach each version. | CODEOWNERS, code owner approval on the protected branch, review requests, audit trail in git | [decision records](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/tree/main/models/decisions), the review requests on !2, !4 and !5, [CODEOWNERS](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/blob/main/.gitlab/CODEOWNERS), and [model-v0.2.0](https://gitlab.com/gitlab-ai-hackathon/transcend-october-2026/43712399/showcase/-/releases/model-v0.2.0) with 0.074 gCO2e to reach it |

When a stage gets its proof, replace **pending** with the link.
